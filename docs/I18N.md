# 多语言 / i18n

翻译成西班牙语的实现说明，以及**新增一种语言需要做什么**。中文为主，底部有西语摘要。

> Para la guía en español (qué toca cada archivo y cómo se prueba), ver
> [`docs/i18n/README-es.md`](i18n/README-es.md).

## 为什么是「叠加式」而不是全量 `t()`

壳层里的中文文案有 2000 多条，散在 `main.js`（3400 行）、`ui/app.js`（2900 行）和
`core/*` 里。把它们逐条改写成 `t('key')` 是一次 2000 处、跨 30 个文件的机械改动：
review 不动、跟上游冲突大、还容易改到逻辑（比较、正则、adb 参数里也有中文）。

所以这里用**叠加式翻译**：代码里的中文原样保留（它是源语言、也是回退），
运行时在「显示」这一层换成目标语言。

- 渲染层：`src/ui/i18n.js` 遍历 DOM 文本节点和 `placeholder / title / aria-label / alt /
  data-tip` 属性，命中词典就替换，并用 `MutationObserver` 跟上 `app.js` 动态渲染的内容。
- 主进程：`src/i18n/index.js` 包住 `dialog.*` 和 `Menu.buildFromTemplate`，
  原生对话框与菜单直接就是目标语言。

新增一种语言的改动量 = 1 个 JSON（+ 可选的手册 Markdown）。核心代码不动。

## 目录

```
src/i18n/
  engine.js          # 纯函数匹配器（精确 + ${占位符} 模板），Node 和浏览器都能用
  index.js           # 主进程：选语言、加载词典、包装 dialog/Menu、挑手册文件
  locales/es-ES.json # 西班牙语词典：{ "中文原文": "traducción" }
src/ui/i18n.js       # 渲染层 overlay（遍历 DOM + MutationObserver）
docs/USER-MANUAL.es.md        # 手册译文（源：docs/USER-MANUAL.md）
src/ui/manual.es.html         # 由 build-manual-html.py --lang es 生成
scripts/i18n-report.js        # 覆盖率报告：还有多少中文没翻译
test/i18n-test.js             # 引擎 + 词典 + 接线 的单元测试
```

## 怎么选语言

`APKSTART_LOCALE` 环境变量 → 否则看系统语言（`app.getLocale()`，按前缀匹配）→
否则回退 `zh-CN`（源语言，overlay 完全空转，行为和没有这个功能一样）。

```powershell
$env:APKSTART_LOCALE="es"; npm start      # 强制西语
npm start                                  # 跟随系统
```

## 新增一种语言（比如日语 ja-JP）

1. **复制词典**：`cp src/i18n/locales/es-ES.json src/i18n/locales/ja-JP.json`
2. **翻译值那一列**。键（中文原文）**不要动**：它就是匹配用的键。
   - 带 `${...}` 的键是模板，值里的占位符名字必须对得上（可以换位置）：
     `"${n} 个应用"` → `"${n} 件のアプリ"`
   - 值的首尾空格、`\n`、`<b>` 等标签要保留。
   - 锚点 id（形如 `6-4-adb-未授权-允许-usb-调试`）不译，它是 HTML id。
3. **看还差多少**：`npm run i18n:report -- --lang ja`（不带参数默认看 `es`）。
   报告里的「sin traducir」就是还没翻的原文，可以直接从 `--missing` 输出拿到 JSON 行。
4. **手册（可选）**：`cp docs/USER-MANUAL.es.md docs/USER-MANUAL.ja.md` 翻译后
   `python docs/build-manual-html.py --lang ja`。注意 `docs/build-manual-html.py`
   顶部的 `L10N` 表要加一组 `ja`（标题、目录、打印按钮等外壳文案）。
   手册的标题锚点沿用中文版的 id（`stable_ids()`），所以 `src/core/manual.js`
   不用改，任何语言都能跳到正确的章节。
5. **跑测试**：`npm test`（含 `test/i18n-test.js`：占位符是否一致、有没有漏译、
   手册锚点是否齐全、页面是否真的加载了 overlay）。

## 已知边界

叠加式翻译只处理「显示」这一层，下面这些仍然会是中文，需要按需在调用处包一层 `i18n.t()`：

- 系统通知：`new Notification({ title, body })`（`main.js` 的 `notify()`）
- 手动设置的窗口标题：`win.setTitle()` / `manualWindow.setTitle()`
- 托盘 tooltip：`tray.setToolTip()`
- 写进磁盘的日志、诊断报告、命令行输出（这些不属于界面，保持中文更利于排查）

这些点在 `es-ES.json` 里已经有译文，包一层即可生效。

## 质量约定

- 术语统一用 [`docs/i18n/GLOSARIO-es.md`](i18n/GLOSARIO-es.md) 里的对照表，
  同一个中文词在不同文件里必须译成同一个西语词。
- 不翻译：产品名、命令、路径、错误码（`0xC0000135`）、`adb` 参数、正则。
- `core/*` 里用于**匹配**安卓报错的正则（如 `/空间不足|ENOSPC/`）绝对不要动：
  那是解析安卓侧输出用的，和界面语言无关。

## Resumen en español

Este proyecto traduce en la capa de presentación: el chino se queda en el código
como idioma de origen y como respaldo, y en tiempo de ejecución se sustituye por
el idioma activo (`APKSTART_LOCALE`, luego el idioma del sistema, luego `zh-CN`).

- Diccionario: `src/i18n/locales/<locale>.json` con pares `"texto original": "traducción"`.
  Las claves no se tocan; los valores con `${nombre}` deben conservar esos marcadores.
- Motor: `src/i18n/engine.js` (coincidencia exacta + plantillas). `src/ui/i18n.js`
  recorre el DOM y observa los cambios; `src/i18n/index.js` traduce diálogos nativos y menús.
- Cobertura: `npm run i18n:report` (o `-- --missing` para sacar lo que falta).
- Manual: `docs/USER-MANUAL.es.md` + `python docs/build-manual-html.py --lang es`.
  Los anclajes son los del manual chino, así que `src/core/manual.js` no cambia.
- Pruebas: `npm test` incluye `test/i18n-test.js`.
- Límites conocidos: notificaciones del sistema, títulos de ventana y tooltips del
  área de notificación siguen en chino hasta que se envuelvan con `i18n.t()`.
