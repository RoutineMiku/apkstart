# Interface translations

The interface (including the startup splash) supports Simplified Chinese (`zh-CN`), Brazilian Portuguese (`pt-BR`),
English (`en`) and Russian (`ru`). Settings → Language saves the selection immediately and reloads
the main window. Existing Android app windows pick up the new language when reopened.
Automatic mode follows the Windows locale, using English for unsupported languages.

Messages live in `src/locales/*.json`. Keep the same keys and numbered placeholders
in all catalogs. Existing `mNNNN` keys identify extracted messages and must not
be renumbered. Use descriptive keys for new messages. Some messages contain trusted
interface HTML; preserve their markup and escape user content before interpolation.
App names, package names, file paths, release notes and raw runtime logs are not
translated. Some diagnostics emitted by the underlying runtime still use Chinese.
The bundled user manual has a Chinese page (`src/ui/manual.html`) and an English
translation (`src/ui/manual.en.html`, used for every non-Chinese locale). Both keep
identical section ids so the troubleshooting issue codes map to the same anchors.

`src/core/i18n.js` handles locale selection and main-process messages. The renderer
loads its catalog through the allowlisted `i18n:get` IPC channel. Static HTML uses
`data-i18n` and `data-i18n-title/placeholder/alt/aria-label/value`; JavaScript uses `tr()`.
No runtime dependency is added for internationalization.

## Validation

```powershell
npm test
npm run test:i18n
npm run test:i18n:ui
```

The UI test uses mocked APIs in an isolated Electron window. It checks language
switching, persistence across reloads, app-launch feedback and settings overflow,
translated context menus, category navigation, cross-category search, diagnostic
tutorial routing and both bundled/download splash variants.
Screenshots are written to `test/out/i18n/`. It does not install APKs or alter the
user's installation. Real Android app startup still needs a manual test.

## Local test installer

```powershell
npm install
npm run build:exe:test
```

Output: `dist/i18n-test/ApkStart-<package version>-i18n.1-Setup.exe` (Windows x64).
This unsigned, unpublished test build uses the same application ID and data paths
as ApkStart. It omits the bundled Android runtime and reuses an existing runtime in
the user data directory; missing runtime components download on demand. It must be
installed in the same location as the current installation to replace that copy.
The installer language and interface language can be selected independently.

## Teste em português

1. Feche o ApkStart pela opção Sair no ícone da bandeja do Windows.
2. Execute o instalador de teste e escolha a mesma pasta da instalação atual.
3. Abra Configurações → Idioma e selecione Português (Brasil).
4. Confira as telas, abra um app Android já instalado e teste a opção English.

O instalador mantém o mesmo identificador e os mesmos caminhos de dados do projeto.
Ele não inclui a imagem Android completa. Logs brutos e alguns diagnósticos internos
ainda podem aparecer em chinês. A compilação é local e não publica uma versão ou PR.
